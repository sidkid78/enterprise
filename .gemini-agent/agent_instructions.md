## Project Context

A Next.js dashboard for operating a multi-agent AI platform: human-in-the-loop (HITL) approval gates, DAG execution traces, workforce enablement, and BIO/ROI billing.

**Only the UI shell exists.** There is no backend, database client, API route, auth, or `.env`. Every figure in the dashboard is a hard-coded literal inside `useState`. The intended full system is specified in `ai_docs/` but has not been built.

## Project-Specific Rules

### 1. Tech Stack

- Framework: Next.js 16.3.2 (App Router, React 19.2.8)
- Language: TypeScript (`strict`), path alias `@/*` → `./src/*`
- Styling: Tailwind CSS v4 — configured CSS-first via `@import` in `src/app/globals.css`. **No `tailwind.config.ts` exists**; `components.json` references one anyway. Do not create it — put theme changes in `globals.css` as CSS variables.
- Components: shadcn v4, `base-nova` style, built on **`@base-ui/react` — not Radix**. There is no `asChild`; Base UI uses `render`. Icons: `lucide-react`.
- Database: none installed. `ai_docs/database_arch copy.md` specifies Supabase/Postgres (RLS, `pgvector`, `pgcrypto`) as the target.
- LLM SDK: none installed. Target is `@google/genai` >= 2.3.0 via the **Interactions API** — see below.

### 2. Architecture Patterns

- `next.config.ts` permanently redirects `/` → `/dashboard`. `src/app/page.tsx` is the untouched create-next-app splash and is unreachable — do not invest in it.
- `src/app/dashboard/page.tsx` is a single `'use client'` component owning all state (`activeTab`, `workspaceId`, `stats`) and switching between four tab components in `src/components/dashboard/`.
- Each tab component receives only `{ workspaceId }` and seeds its own mock state. The tenant dropdown does **not** currently re-fetch or re-filter. That prop is the intended tenant key when real data is wired.
- The blueprints describe an orchestrator-worker DAG, a triple-gate governance plane (injection/PII → JSON validation → critic), a FinOps model cascade, and stateful HITL pause/resume. None of it is implemented — the UI only renders what those stages *would* produce.

### 3. File & Directory Conventions

- Source: `src/` — `app/` (routes), `components/dashboard/` (feature tabs), `components/ui/` (shadcn), `lib/` (`cn` helper)
- Design docs: `ai_docs/` — read before implementing any backend surface
- Specs: `./specs/current/` for active work, `./specs/archive/` for completed (both currently empty)
- Tests: none. There is no test framework, script, or directory. Do not invent one without asking.

### 4. Critical Conventions

- **Two styling systems coexist.** `components/dashboard/*` uses hand-rolled Tailwind literals on a fixed `slate-950`/`cyan-400` dark palette with no dark-mode variants. `components/ui/*` uses semantic tokens (`bg-primary`, `text-muted-foreground`) with `@custom-variant dark`. Match the file you are editing; never mix the two idioms in one component.
- **Next.js 16 differs from training data.** Read the relevant guide in `node_modules/next/dist/docs/` before writing framework code. `LayoutProps<"/">` in `layout.tsx` is a generated global type, not an import.
- The model ids in the mock DAG data are **real and current** — `gemini-3.5-flash-lite` → `gemini-3.7-flash` → `gemini-3.1-pro-preview` is a valid cheap/mid/reasoning cascade. Keep them as-is. See "Gemini API" below.
- `.claude/skills/*` are **directory junctions** into `.agents/skills/*`. Edit under `.agents/skills/`; never replace a junction with a real directory. `skills-lock.json` hash-tracks their upstream sources — treat them as vendored.
- `AGENTS.md` at the repo root is regenerated by `next dev`. Deleting it from a diff just recreates it; commit it alongside your work.

### 5. Gemini API

Use the **Interactions API** (`client.interactions.create()`), not `generateContent`. Requires `@google/genai` >= 2.3.0 — the legacy `@google/generative-ai` package is deprecated.

```ts
import { GoogleGenAI } from "@google/genai";
const client = new GoogleGenAI({});

const interaction = await client.interactions.create({
  model: "gemini-3.7-flash",
  input: "…",
});
console.log(interaction.output_text);
```

Current models — the cascade in the mock DAG is correct:

| Tier | Model | Use |
| --- | --- | --- |
| Cheap | `gemini-3.5-flash-lite` | High-throughput decomposition, routing, classification |
| Mid | `gemini-3.7-flash` | Default; agentic and multimodal work |
| Reasoning | `gemini-3.1-pro-preview` | Deep audit/analysis steps |

Never use `gemini-2.5-*`, `gemini-2.0-*`, or `gemini-1.5-*` — deprecated. Substitute `gemini-3.7-flash`.

Rules that matter for this project's design:

- `tools`, `system_instruction`, and `generation_config` are **interaction-scoped** — re-specify them on every turn.
- **Multi-turn uses `previous_interaction_id`**, not a manual history array. This is the natural fit for the blueprint's HITL pause/resume: persist the interaction id in the gate record and resume from it after human sign-off.
- **Long-running work uses `background: true`** plus polling on `interactions.get(id)` (`status`: `completed` / `in_progress` / `requires_action` / `failed` / `cancelled`). `requires_action` is the status a HITL gate should map onto.
- Interactions are **stored by default** (`store: true`; 55-day retention on paid tier). `store: false` opts out but **disables both `previous_interaction_id` and `background`** — so the HITL and DAG flows require storage on. Note this against the blueprint's PII/zero-trust gate: masking must happen before the call, since the input is retained server-side.
- A response is a typed `steps[]` timeline (`user_input`, `model_output`, `thought`, `function_call`/`function_result`, `google_search_call`/`_result`, …). This maps directly onto the `DagNode` trace the dashboard renders — prefer deriving trace nodes from `steps` over inventing a parallel structure.
- Prefer `interaction.output_text` / `output_image` / `output_audio` helpers over indexing into `steps`.
- Streaming is `stream: true` with `step.delta` events, not `generateContentStream`.
- `temperature`, `top_p`, and `top_k` are deprecated on current models. Use `thinking_level` (`minimal` | `low` | `medium` | `high`) — not `thinking_budget`.

**The code samples in `ai_docs/` predate this API** and have not been migrated: they mix `ai.models.generateContent`, `ai.models.embedContent`, and `text-embedding-004`. Follow the rules above over the blueprint samples, and consult the `gemini-interactions-api` skill plus the hosted docs before writing any call.

## Common Workflows

```bash
npm run dev      # dev server on :3000 (rewrites the agent-rules block in AGENTS.md)
npm run build    # production build
npm run lint     # eslint, flat config
npx tsc --noEmit # typecheck — there is no `typecheck` script
```

**Adding a UI component:** use the shadcn CLI so the `base-nova` registry style is preserved. Consult `.agents/skills/shadcn/` — especially `rules/base-vs-radix.md`.

**Replacing mock data with real data:** the hard-coded `useState` arrays in each dashboard tab define the shape the UI expects. Preserve those TypeScript interfaces (`PendingGate`, `DagNode`) as the contract when introducing a data layer, and check the shape against `ai_docs/database_arch copy.md` before diverging.

**Note:** `commands/`, `workflows/`, and `logs/` are empty scaffolding. Nothing reads them yet.
